Erste Schritte

  1. Verwenden Sie beim ersten Start den leeren Verbindungstab. Bei späteren Starts werden Ihre bisherigen Tabs wiederhergestellt, ohne die Verbindungen automatisch erneut aufzubauen. Erstellen Sie bei Bedarf mit Strg/⌘+T einen neuen.
  2. Wählen Sie unter Schnellverbindung ein Protokoll aus und geben Sie Host, Port, Benutzername und Passwort ein. Geben Sie im Host-Feld nur einen Hostnamen oder eine IP-Adresse ein - kein URL-Schema, keinen Port, Pfad oder Benutzernamen. Neue FTP- und FTPS-Verbindungen, die Sie direkt über die Schnellverbindung einrichten, verwenden den passiven Modus. Konfigurieren Sie für den aktiven Modus einen gespeicherten Eintrag im Servermanager.
  3. Wählen Sie Verbinden. Prüfen Sie Zertifikats- und Hostschlüsselabfragen, bevor Sie diese bestätigen.
  4. Wählen Sie links ein lokales Verzeichnis aus und wechseln Sie rechts zum Zielverzeichnis auf dem Server.
  5. Markieren Sie Dateien oder Verzeichnisse und wählen Sie Hochladen oder Herunterladen. Der Übertragungsbereich unten im Fenster zeigt den Fortschritt.

Tipp: Verwenden Sie den Servermanager für private Schlüssel, die Anmeldung über einen SSH-Agenten oder die interaktive Anmeldung, Startverzeichnisse, die FTP-Zeichenkodierung, den FTP-Datenverbindungsmodus und regelmäßig verwendete Verbindungen.

Verbindungen und Anmeldung

Verfügbare Verbindungsarten
Protokoll Üblicher Port Schutz Anmeldung
FTP 21 Keiner Passwort
Explizites FTPS 21 TLS beginnt nach dem Verbindungsaufbau Passwort
Implizites FTPS 990 TLS beginnt sofort Passwort
SFTP 22 SSH Passwort, privater Schlüssel, SSH-Agent, interaktive Tastatureingabe oder Passwort + interaktive Tastatureingabe

Beim Auswählen eines Protokolls wechselt der angezeigte Port zum üblichen Standardwert. Der Server kann jedoch einen anderen Port verwenden. Neue, nicht gespeicherte Schnellverbindungen verwenden die Passwortanmeldung. Erstellen Sie für andere SFTP-Anmeldearten einen gespeicherten Server. Wenn Sie einen Tab für einen gespeicherten Server mit unveränderten Verbindungsdaten erneut verbinden, bleiben dessen gespeicherte Anmeldeart und FTP-Datenverbindungsmodus erhalten.

Neue, nicht gespeicherte FTP- und FTPS-Verbindungen verwenden den passiven Modus, der für die meisten Verbindungen empfohlen wird. Für einen gespeicherten FTP- oder FTPS-Server können Sie stattdessen Aktiv auswählen. Im passiven Modus baut havRemote die Datenverbindung zum Server auf. Im aktiven Modus verbindet sich der Server mit Ihrem Computer. Firewall und Netzwerk müssen daher eingehende Verbindungen zulassen. Standardmäßig verwendet havRemote dieselbe lokale Adresse wie beim Verbindungsaufbau zum Server und einen vom Betriebssystem gewählten temporären Port.

Lokale Adresse im aktiven Modus (optional) lässt Sie eine andere IPv4- oder IPv6-Adresse auswählen, die diesem Computer bereits zugewiesen ist. Lassen Sie das Feld für die automatische Auswahl leer. Das kann bei einem VPN oder mehreren Netzwerkverbindungen hilfreich sein, doch der Server muss die gewählte Adresse erreichen können. havRemote verwendet sie sowohl zum Empfangen der eingehenden Verbindung als auch als Zieladresse für den Server. Es kann nicht an einer Adresse auf die Verbindung warten und dem Server eine andere mitteilen, etwa die öffentliche Adresse eines Routers. Geben Sie keine Klammern, keinen Port, Hostnamen und keine URL-Syntax an.

Wählen Sie Interaktive Tastatureingabe, wenn der Server alle Abfragen direkt bereitstellt. Innerhalb eines Austauschs kann er sowohl nach einem Passwort als auch nach einem TOTP-Code fragen. Wählen Sie Passwort + interaktive Tastatureingabe, wenn der Server zuerst das Kontopasswort annimmt und erst danach eine weitere Abfrage anbietet, üblicherweise für TOTP. Das erste Passwort kann gespeichert werden, Antworten auf interaktive Abfragen gelten jedoch nur für die aktuelle Verbindung.

Privater Schlüssel liest die ausgewählte Schlüsseldatei direkt und verwendet keinen SSH-Agenten. SSH-Agent verwendet Schlüssel, die ein laufender, kompatibler SSH-Agent bereitstellt. Wird kein Schlüssel akzeptiert, wechselt havRemote nicht unbemerkt zu einem anderen Agenten oder einer anderen Anmeldeart.

Tipp: Die Anmeldung über einen SSH-Agenten erfordert einen laufenden Agenten mit geladenem privaten Schlüssel. havRemote startet einen Agenten nicht automatisch.

SSH-Agent-Auswahl je nach Betriebssystem
  • Windows: havRemote verwendet Pageant, wenn es ausgeführt wird. Andernfalls wird der Windows-OpenSSH-Agent versucht.
  • Linux und macOS: Der OpenSSH-kompatible Agent wird über die von havRemote geerbte Umgebungsvariable SSH_AUTH_SOCK bestimmt.

Ein Hostschlüssel-Fingerabdruck des SFTP-Servers identifiziert den Server und muss bei einer Vertrauensabfrage geprüft werden. Ein nach einer Agentenanmeldung gemeldeter Fingerabdruck der Clientidentität bezeichnet den Schlüssel, den der Server von Ihnen akzeptiert hat. Diese Fingerabdrücke stehen für die beiden unterschiedlichen Seiten der Verbindung und stimmen normalerweise nicht überein.

Server speichern

  1. Öffnen Sie Datei → Servermanager oder drücken Sie Strg/⌘+S.
  2. Wählen Sie Neuer Server, geben Sie einen aussagekräftigen Namen ein und wählen Sie das Protokoll.
  3. Geben Sie Endpunkt und Anmeldedaten ein. Sie können außerdem ein lokales und entferntes Startverzeichnis sowie bei FTP oder FTPS den Datenverbindungsmodus und optional eine andere lokale Adresse für den aktiven Modus auswählen.
  4. Speichern Sie die Änderungen mit OK oder wählen Sie Verbinden, um zu speichern und eine Verbindung zum ausgewählten Server herzustellen. Abbrechen verwirft Ihre Änderungen.

Mit Neuer Ordner erstellen Sie eine verschachtelte Ordnerstruktur. Ziehen Sie Server oder Ordner oberhalb oder unterhalb eines anderen Eintrags, um sie neu anzuordnen, auf die Mitte eines Ordners, um sie hineinzuverschieben, oder auf eine freie Fläche, um sie auf die oberste Ebene zu verschieben. Server und Ordner können in beliebiger Reihenfolge gemischt werden. Duplizieren kopiert einen ausgewählten Server oder rekursiv einen ausgewählten Ordner mit allen Unterordnern und Servern. Gespeicherte Passwörter und Schlüssel-Passphrasen werden von keiner Kopie gemeinsam verwendet. Geben Sie diese bei Bedarf separat ein.

Server und Ordner müssen innerhalb desselben Ordners (einschließlich der obersten Ebene) unterschiedliche Namen haben. In verschiedenen Ordnern können Namen erneut verwendet werden. Beim Duplizieren eines Ordners bleiben die Namen innerhalb der Kopie unverändert.

Beim Löschen eines Ordners im Servermanager werden der Ordner und alle darin verschachtelten gespeicherten Ordner und Server entfernt. Die Änderung wird erst beim Speichern mit OK oder Verbinden übernommen. Dateien oder Verzeichnisse auf einem entfernten Server werden dadurch niemals gelöscht.

Wählen Sie im Servermanager einen Server und dann Verbinden oder öffnen Sie einen gespeicherten Server mit dem Pfeil neben der Servermanager-Schaltfläche im Hauptfenster. Wenn ein Ordner oder kein Eintrag ausgewählt ist, steht Verbinden nicht zur Verfügung. havRemote verwendet nach Möglichkeit den aktuellen unveränderten Tab. Andernfalls wird ein vorhandener Tab desselben gespeicherten Servers aktiviert und bei Bedarf erneut verbunden. Nur wenn kein passender Tab verfügbar ist, wird ein neuer geöffnet.

Server importieren und exportieren

Wählen Sie im Servermanager Exportieren..., um den ausgewählten Server, einen ausgewählten Ordner mit seinem gesamten Inhalt oder alle Einträge in eine .cson-Datei zu exportieren. Die aktuell bearbeiteten Einstellungen werden exportiert ohne den Servermanager-Dialog zu speichern. Ordnerstruktur und Reihenfolge bleiben erhalten.

Mit Importieren... laden Sie einen havRemote-Serverexport in den ausgewählten Ordner, neben einen ausgewählten Server oder bei leerer Auswahl auf die oberste Ebene. Prüfen Sie vor dem Import die Vorschau. Vorhandene Einträge bleiben erhalten. Bei Namenskonflikten werden umbenannte Kopien zur Bestätigung angezeigt. Speichern Sie die importierten Einträge mit OK oder Verbinden. Abbrechen im Servermanager verwirft die Änderungen.

Exporte enthalten keine Passwörter, Anmeldedaten-Kennungen, Vertrauenseinträge, Schlüsseldateien oder deren lokale Pfade, lokalen Startordner oder lokalen Adressvorgaben für den aktiven Modus. Wählen Sie für importierte Server mit privatem Schlüssel vor dem Speichern oder Verbinden eine lokale Schlüsseldatei aus. Geben Sie fehlende Anmeldedaten bei Bedarf erneut ein und prüfen Sie die Serveridentität wie gewohnt. Servernamen, Benutzernamen und entfernte Pfade sind weiterhin private Metadaten. Prüfen Sie eine Datei vor dem Weitergeben.

Verbindung trennen

Während einer aktiven Verbindung wird die Schaltfläche Verbinden zu Trennen. Dabei bleiben der Tab und sein lokaler Browser geöffnet. Übertragungen oder extern bearbeitete Dateien dieser Verbindung können eine Bestätigung erfordern, bevor die Verbindung oder der Tab geschlossen werden kann.

Verbindungstabs

Jeder Tab besitzt eine eigene Verbindung, einen lokalen Browser, einen Serverbrowser und ein gemerktes Verzeichnispaar. Beim Wechseln des Tabs stellt havRemote dessen Schnellverbindungsfelder und beide Dateiansichten wieder her. Daher müssen Sie den lokalen Browser nicht für jeden Server erneut einstellen.

  • Erstellen Sie mit der Plus-Schaltfläche oder Strg/⌘+T einen Tab.
  • Schließen Sie den aktuellen Tab über dessen Schließen-Schaltfläche, mit einem Mittelklick oder Strg/⌘+W.
  • Ziehen Sie Tabs mit der Maus, um sie neu anzuordnen.
  • Ein neuer, leerer Tab beginnt mit ausgewähltem SFTP.

Beim nächsten Start stellt havRemote die geöffneten Tabs in ihrer bisherigen Reihenfolge wieder her und wählt den Tab aus, der beim Beenden aktiv war. Die Identitäten gespeicherter Server und von Schnellverbindungen sowie beide Browserpfade werden wiederhergestellt. Die Verbindungen bleiben jedoch getrennt und Geheimnisse werden niemals im Arbeitsbereich gespeichert. Verbinden Sie die benötigten Tabs erneut.

Warteschlange und Meldungsprotokoll gelten für alle Tabs. Die Spalte Verbindung zeigt zu welchem Tab eine Übertragung gehört. Mit der Schaltfläche zum Leeren neben der Überschrift des Meldungsprotokolls verwerfen Sie die derzeit angezeigten Meldungen.

Dateibrowser

Der linke Browser zeigt lokale Dateien, der rechte den aktiven Server. Navigieren Sie mit dem Pfadfeld, Hoch, Aktualisieren oder dem Eintrag ... Drücken Sie nach Eingabe eines Pfads Eingabe. Durch Aktivieren eines Verzeichnisses wird es geöffnet. Bei einer regulären Datei wird ein Upload oder Download eingereiht.

  • Klicken Sie auf eine Spaltenüberschrift, um zu sortieren. Ein weiterer Klick kehrt die Richtung um. Ziehen Sie die Trennlinie einer Überschrift, um die Spaltenbreite zu ändern. Sortierung und Spaltenbreiten werden für lokale und entfernte Listen getrennt gespeichert und in allen Verbindungstabs verwendet.
  • Die Spalte Typ kennzeichnet reguläre Dateien anhand ihrer letzten Dateiendung, etwa als TXT-Datei oder GZ-Datei für archive.tar.gz. Dateien ohne Endung, darunter .gitignore, erscheinen weiterhin als Datei. Beim Sortieren nach Typ werden Dateien unabhängig von Groß- und Kleinschreibung nach Endung und anschließend nach Namen sortiert. Ordner und .. bleiben in beiden Richtungen oben.
  • Öffnen Sie das Kontextmenü einer Auswahl mit einem Sekundärklick oder unter macOS mit Control-Klick, um auf die verfügbaren Aktionen zum Hoch- oder Herunterladen, Bearbeiten, Umbenennen, Löschen, Erstellen, Ändern von Berechtigungen und Aktualisieren zuzugreifen. Unter Windows und Linux können Sie außerdem die Kontextmenü-Taste oder Umschalt+F10 verwenden.
  • Ziehen Sie ausgewählte lokale Elemente auf die Serverliste, um sie hochzuladen oder entfernte Elemente auf die lokale Liste, um sie herunterzuladen. Diese anwendungsinternen Ablagevorgänge funktionieren zwischen den beiden Listen desselben Verbindungstabs und verwenden das aktuell angezeigte Zielverzeichnis. Sie können außerdem Dateien oder Verzeichnisse aus dem Dateimanager auf eine verbundene Serverliste ziehen, um sie hochzuladen.
  • Die Serverliste kann Berechtigungen sowie Besitzer/Gruppen-Daten anzeigen, wenn der Server sie liefert. Ein leerer Wert bedeutet gewöhnlich, dass das Protokoll oder der Server diese Angabe nicht bereitgestellt hat.
  • Symbolische Verknüpfungen werden als Links angezeigt, bei rekursiven Übertragungen jedoch nie verfolgt.
  • Verwenden Sie Aktualisieren, wenn ein anderes Programm oder ein serverseitiger Prozess das Verzeichnis verändert haben könnte. havRemote aktualisiert außerdem ein sichtbares lokales Ziel nach einem Download und ein sichtbares entferntes Ziel nach einem Upload.

Übertragungen, Konflikte und Fortsetzen

Übertragung starten

Markieren Sie ein oder mehrere lokale Elemente und wählen Sie Hochladen oder markieren Sie entfernte Elemente und wählen Sie Herunterladen. Verzeichnisse werden rekursiv erfasst und übertragen. Dateien aus verschiedenen Verbindungstabs teilen sich die Warteschlange und die eingestellte Obergrenze für gleichzeitige Übertragungen.

Warteschlangenansichten und Aktionen

Das Kontextmenü bietet dieselben Aktionen wie die Schaltflächen mit derselben Verfügbarkeit sowie zusätzlich Alle kopieren.

  • Warteschlange enthält wartende, erfasste, laufende und pausierte Vorgänge.
  • Fehlgeschlagen enthält Übertragungen, die mit einem Fehler beendet oder abgebrochen wurden.
  • Abgeschlossen enthält erfolgreich beendete Vorgänge.
  • Pause, Abbrechen und Erneut versuchen erfordern genau eine markierte Übertragung, für die die Aktion möglich ist. Bei mehreren markierten Einträgen sind sie deaktiviert.
  • Entfernen erfordert genau einen markierten abgeschlossenen, fehlgeschlagenen oder abgebrochenen Eintrag und löscht ihn aus den Warteschlangendaten. Beim Entfernen einer fehlgeschlagenen Übertragung ist eine Bestätigung erforderlich, da deren Wiederholungs- und Wiederherstellungsinformationen verworfen werden.
  • Leeren entfernt alle Einträge der aktuellen Ansicht Fehlgeschlagen oder Abgeschlossen und zeigt bei fehlgeschlagenen Übertragungen dieselbe Warnung. Unvollständige lokale Dateien und temporäre Dateien auf dem Server bleiben zur Sicherheit erhalten.
  • Kopieren kopiert markierte Einträge in jeder der drei Ansichten. Verwenden Sie die Kopieren-Schaltfläche, die Kontextmenü-Aktion oder Strg/⌘+C, während die Übertragungsliste den Fokus hat. Markieren Sie mehrere Einträge mit Strg/⌘ oder Umschalt oder drücken Sie Strg/⌘+A, um alle Einträge der fokussierten Liste auszuwählen.
  • Alle kopieren im Kontextmenü kopiert die gesamte aktuelle Ansicht. Kopieren ist nur bei einer Auswahl verfügbar. Alle kopieren ist verfügbar, sobald die Ansicht nicht leer ist.

Übertragungen werden als tabulatorgetrennter Klartext mit übersetzten Spaltenüberschriften, allen angezeigten Spalten und vollständigen Fehlerdetails kopiert. Kopieren reiht Übertragungen weder erneut ein noch ändert es deren Status.

Wählen Sie in der Schaltflächenleiste oder im Kontextmenü Exportieren... → Auswahl exportieren... oder Alle exportieren..., um aus jeder Übertragungsansicht einen .csv-Bericht zu speichern. Der Bericht erfasst die Einträge vor dem Öffnen des Speicherdialogs mit übersetzten Überschriften, aktueller Spaltenreihenfolge und vollständigen Fehlerdetails. Der Auswahlexport benötigt markierte Einträge. Der Export der gesamten Ansicht benötigt eine nicht leere Ansicht. Berichte ändern keine Übertragungen und können nicht zum Wiederherstellen einer Warteschlange importiert werden. Nur noch in der Ansicht vorhandene Einträge können exportiert werden.

CSV-Berichte verwenden UTF-8 und durch Kommas getrennte, in Anführungszeichen gesetzte Felder. Wählen Sie beim Öffnen in einer Tabellenkalkulation bei Bedarf UTF-8 und Komma als Trennzeichen. Geheimnisse und Steuerzeichen werden bereinigt. Formelähnlichem Text wird ein Apostroph vorangestellt. Das Überschreiben vorhandener Dateien erfordert eine Bestätigung. Anwendungskonfiguration, Übertragungswiederherstellung und gespeicherte Hostschlüssel dürfen nicht durch einen Export ersetzt werden.

Die Spalten Geschwindigkeit und Restzeit zeigen für laufende Dateiübertragungen einen aktuellen Durchschnitt. Die Restzeit ist nur verfügbar, wenn die Gesamtgröße bekannt ist. Bei pausierten, wartenden und beendeten Einträgen sowie beim Erfassen von Verzeichnissen bleiben diese Felder leer.

Fehlgeschlagene Uploads und Downloads erzeugen einen Fehlereintrag im Nachrichtenprotokoll und zeigen einen Fehlerdialog mit der Verbindung, Übertragungsrichtung, dem Pfad auf dem Server und dem Fehler an. Zeitlich nahe beieinander auftretende Fehler werden in einer Meldung zusammengefasst. Die Übertragungen bleiben unter Fehlgeschlagen. Markieren Sie nach dem Beheben des Problems einen Eintrag und wählen Sie Erneut versuchen. Beim Pausieren oder Abbrechen werden diese Fehlermeldungen nicht ausgelöst. Beim Start von havRemote wiederhergestellte Fehler lösen sie nicht erneut aus.

FTP/FTPS-Uploads melden unzureichenden Speicherplatz oder ein überschrittenes Speicherlimit, wenn der Server diesen Grund angibt. Scheitert die Verbindung, bevor eine abschließende Antwort verfügbar ist, kann havRemote möglicherweise nur eine Verbindungsunterbrechung melden. Bitten Sie bei unklarer Ursache den Serveradministrator, die Serverprotokolle zu prüfen. Teilweise hochgeladene Dateien bleiben erhalten, damit Sie nach dem Beheben des Problems einen erneuten Versuch starten oder die Übertragung sicher fortsetzen können.

Ein Server kann einen abschließenden Vorgang bereits ausgeführt haben, auch wenn seine Antwort verloren ging. havRemote wiederholt destruktive Vorgänge mit ungewissem Ergebnis nicht automatisch. Prüfen Sie das Ziel, bevor Sie einen erneuten Versuch bestätigen.

Zielkonflikte

Mit Nachfragen, der anfänglichen Standardeinstellung, bietet havRemote die für die jeweilige Übertragung sicheren Möglichkeiten an:

  • Überschreiben ersetzt das Ziel.
  • Überspringen lässt das Ziel unverändert.
  • Umbenennen überträgt das neue Element unter einem anderen Namen.
  • Fortsetzen führt eine geprüfte Teilübertragung weiter.

Eine Auswahl kann auf verbleibende Konflikte in der Warteschlange angewendet werden. Sicherheitsrelevante Konflikte, beispielsweise eine während externer Bearbeitung auf dem Server geänderte Datei, werden immer einzeln behandelt.

Wenn Sie eine eingehende Datei umbenennen, merkt sich havRemote das gewählte Ziel für erneute Versuche, auch nach einem Neustart der Anwendung. Bei Verzeichnisübertragungen wird der gewählte Name für jede Datei einzeln gespeichert. Die Informationen zum Fortsetzen bleiben diesem Ziel zugeordnet. Bei einem neuen Namen werden keine Wiederherstellungsdaten für das alte Ziel verwendet.

Teildateien und sicheres Fortsetzen

Downloads verwenden eine gleichnamige Datei mit der Endung .havremote.part. Uploads verwenden einen temporären Namen auf dem Server, sofern dieser das unterstützt. Fortsetzen wird nur angeboten, wenn die aufgezeichneten Quell- und Zielmetadaten weiterhin übereinstimmen. Starten Sie andernfalls neu oder wählen Sie eine andere Konfliktaktion.

Das Fortsetzen von FTP- und FTPS-Uploads muss vom Server unterstützt werden. Ist dies nicht der Fall, starten Sie den Upload von vorn oder bitten Sie den Serveradministrator das Fortsetzen von Uploads zu erlauben.

Dateioperationen und Berechtigungen

Lokale Dateien

  • Neuer Ordner erstellt ein Verzeichnis am aktuellen Ort.
  • Bearbeiten öffnet eine markierte Datei im eingerichteten externen Editor.
  • Umbenennen bearbeitet den Namen des ausgewählten Elements.
  • Löschen verschiebt ausgewählte Elemente nach Möglichkeit in den Papierkorb. Ist dies nicht möglich, können betroffene Elemente endgültig gelöscht werden.

Dateien auf dem Server

  • Erstellen Sie eine leere Datei oder ein Verzeichnis am aktuellen entfernten Ort.
  • Benennen Sie Dateien und Verzeichnisse um.
  • Öffnen Sie eine reguläre Datei zur externen Bearbeitung.
  • Ändern Sie den Berechtigungsmodus eines oder mehrerer unterstützter Elemente.
  • Löschen Sie ausgewählte Elemente endgültig. Entfernte Verzeichnisse werden rekursiv gelöscht.

Warnung: Das Löschen auf dem Server ist endgültig und kann von havRemote nicht rückgängig gemacht werden. Lesen Sie die Bestätigung besonders bei Verzeichnissen oder einer Mehrfachauswahl sorgfältig.

Wenn eine der Dateilisten den Fokus hat, drücken Sie Entf ohne Zusatztasten, um ein oder mehrere markierte Elemente mit derselben Bestätigung wie über die Schaltfläche zu löschen. Entfernte Elemente werden endgültig gelöscht. Lokale Elemente werden nach Möglichkeit in den Papierkorb verschoben. Andernfalls können sie endgültig gelöscht werden. Während Sie einen Pfad eingeben oder einen Dateinamen bearbeiten, löscht dieses Tastenkürzel keine Dateien. Umschalt+Entf umgeht die Bestätigung nicht und ändert auch das lokale Löschverhalten nicht.

Entfernte Berechtigungen ändern

Markieren Sie eine oder mehrere entfernte Dateien oder Verzeichnisse und wählen Sie Berechtigungen. Legen Sie die Lesen-/Schreiben-/Ausführen-Bits für Besitzer, Gruppe und Sonstige sowie optional setuid, setgid und das Sticky-Bit fest oder geben Sie einen exakten drei- oder vierstelligen Oktalmodus wie 0755 ein. Die Verfügbarkeit hängt vom Server ab. havRemote ändert keine Berechtigungen des entfernten Wurzelverzeichnisses, symbolischer Verknüpfungen oder spezieller Dateien.

Externes Bearbeiten

Öffnen Sie die Einstellungen, um die Standardanwendung des Betriebssystems oder einen benutzerdefinierten Editor auszuwählen. Eine benutzerdefinierte Argumentvorlage muss genau einmal {file} enthalten. havRemote setzt den Dateipfad als einzelnes, wörtliches Argument ein, ohne eine Befehlsshell aufzurufen.

Lokale Dateien

Markieren Sie eine lokale Datei und wählen Sie Bearbeiten. Falls der Dateityp bei Verwendung der Standardanwendung gesperrt ist, wählen Sie einen vertrauenswürdigen benutzerdefinierten Editor, um die Datei als Daten zu öffnen.

Dateien auf dem Server

havRemote lädt eine private Arbeitskopie herunter, öffnet sie im Editor, überwacht stabile Speichervorgänge und lädt Änderungen über die normale Warteschlange hoch. Vor dem Ersetzen prüft havRemote, ob die Datei auf dem Server seit dem Öffnen verändert wurde. In diesem Fall fragt die Anwendung nach, bevor sie die neuere Version überschreibt.

havRemote geöffnet lassen: Lassen Sie Verbindung und Tab während der Bearbeitung geöffnet. Falls Überwachung, Prüfung, Trennung oder Beenden einen sicheren Upload verhindern, behält havRemote die lokale Wiederherstellungskopie und meldet ihren Speicherort.

Einstellungen und Verlauf

Darstellung und Sprache

Im Einstellungsdialog können Sie ein helles oder dunkles Design und eine der verfügbaren Sprachen auswählen. Sprachänderungen werden sofort angewendet. Eine Designänderung wird nach einem Neustart von havRemote wirksam.

Öffnen Sie Hilfe → Hilfe anzeigen oder drücken Sie F1, um die Hilfe in der ausgewählten Anwendungssprache zu lesen. Ist keine passende Hilfeseite installiert, öffnet havRemote stattdessen die englische Hilfe.

Übertragungen und Verbindungen

Gleichzeitige Übertragungen begrenzt die Anzahl der Dateiübertragungen, die über alle Verbindungstabs hinweg ausgeführt werden und wird nach einem Neustart wirksam. Das Verbindungszeitlimit begrenzt die Dauer eines neuen Verbindungsaufbaus. Das Leerlaufzeitlimit begrenzt, wie lange ein Befehl ohne Netzwerkfortschritt bleiben darf. Änderungen der Zeitlimits gelten nach dem erneuten Verbinden eines Tabs.

Für FTP/FTPS-Dateiuploads und -downloads gilt ein separates Zeitlimit bei zu geringer Übertragungsgeschwindigkeit: Die Übertragung schlägt fehl, wenn der gemessene Durchsatz 30 Sekunden lang unter 1 Byte/s bleibt. Dies gilt im passiven und aktiven Modus, auch für explizites und implizites FTPS. Die Gesamtdauer einer Übertragung wird dadurch nicht begrenzt. Kurze Unterbrechungen sind erlaubt. Bei einer Zeitüberschreitung bleiben Teildateien zum sicheren Fortsetzen erhalten. Ein automatischer Wiederholungsversuch erfolgt nicht. Das Leerlaufzeitlimit gilt weiterhin für FTP-Befehlsantworten und SFTP-Vorgänge.

Als Standardaktion bei Konflikten stehen Nachfragen, Überschreiben, Überspringen, Eingehendes Element umbenennen und Fortsetzen, wenn sicher zur Auswahl. Eine Änderung gilt sofort für neu eingereihte Übertragungen. Vorhandene Warteschlangeneinträge behalten die Richtlinie, mit der sie erstellt wurden.

Nach dem Speichern einer Änderung am Design oder an der Anzahl gleichzeitiger Übertragungen bietet havRemote einen sofortigen Neustart an. Lehnen Sie ab, um diese Änderungen erst beim nächsten Start anzuwenden. Die Abfrage warnt vor nicht abgeschlossenen Übertragungen und in externen Editoren geöffneten Dateien: Unterbrochene Übertragungen erscheinen bei der Wiederherstellung pausiert. Der Neustart beendet die Überwachung bearbeiteter Dateien, sodass spätere Speichervorgänge im Editor nicht mehr automatisch hochgeladen werden.

Schnellverbindungsverlauf

Nach einer erfolgreichen, nicht gespeicherten Schnellverbindung merkt sich havRemote bis zu 20 zuletzt verwendete Endpunkte. Über die Verlauf-Schaltfläche können Sie einen Endpunkt erneut verwenden oder die gesamte Liste löschen. Der Verlauf speichert nur Protokoll, Host, Port und Benutzernamen - niemals das Passwort. Beim Löschen werden auch die gemerkten Verzeichnispaare dieser Endpunkte entfernt.

Gemerkter Arbeitsbereich

havRemote merkt sich geöffnete Tabs und ihre Reihenfolge, den ausgewählten Tab, lokale und entfernte Verzeichnisse für gespeicherte Server und zuletzt verwendete Endpunkte, Sortierung und Spaltenbreiten der lokalen und entfernten Listen sowie Größe, Position und maximierten Zustand des Hauptfensters. Wählen Sie Einstellungen → Hauptfenster → Standardgröße wiederherstellen und klicken Sie anschließend auf OK, um die Standardabmessungen anzuwenden und zu speichern. Abbrechen lässt die Fensterposition und -größe unverändert. Beim Öffnen eines gespeicherten Servers wird zuerst dessen gemerktes Verzeichnispaar wiederhergestellt. Die eingestellten Startverzeichnisse werden nur verwendet, wenn noch kein gemerktes Paar vorhanden ist.

Wiederherstellung von Übertragungen

Nicht abgeschlossene und fehlgeschlagene Übertragungen werden getrennt in queue.cson gespeichert. Den Speicherort finden Sie unter Konfigurationsdateien und Speicherorte. Nach einem Neustart erscheint unterbrochene Arbeit pausiert in einem wiederhergestellten Verbindungstab. Wählen Sie diesen Tab, stellen Sie die Verbindung zum selben Server und exakt gleichen Endpunkt her und wählen Sie anschließend Erneut versuchen. Abgeschlossene und abgebrochene Übertragungen werden nicht als dauerhafter Verlauf behalten. Die Warteschlangendatei enthält Pfade, Endpunktidentität, Fortschritt, Fehler und Metadaten für sicheres Fortsetzen, jedoch keine Passwörter oder Schlüssel-Passphrasen.

Wenn die Warteschlangendatei nicht geladen werden kann: havRemote meldet den Fehler und lässt die Datei unverändert. Übertragungen bleiben nutzbar, die Warteschlange wird in dieser Sitzung jedoch nicht gespeichert. Neue Änderungen gehen daher bei einem Neustart verloren. Schließen Sie havRemote, sichern Sie queue.cson, korrigieren oder verschieben Sie die Datei und starten Sie die Anwendung neu, um die Wiederherstellungsdaten erneut speichern zu können. havRemote setzt eine ungültige Warteschlange nicht automatisch zurück.

Updates

Wählen Sie Hilfe → Nach Updates suchen, um auf GitHub nach der neuesten veröffentlichten havRemote-Version zu suchen, die nicht als Vorabversion gekennzeichnet ist. Eine manuelle Suche wird auch ausgeführt, wenn automatische Suchen deaktiviert sind oder diese Version zuvor übersprungen wurde.

Einmal täglich automatisch nach Updates suchen ist standardmäßig aktiviert. Beim Start prüft havRemote nur, wenn in den letzten 24 Stunden kein Versuch abgeschlossen wurde. Diese Version überspringen unterdrückt automatische Hinweise nur für genau diese Version. Eine neuere Veröffentlichung wird weiterhin angezeigt und eine manuelle Suche zeigt auch die übersprungene Version.

Veröffentlichungshinweise werden als schreibgeschützter Klartext angezeigt. Herunterladen öffnet den Download-Link in Ihrem Standardbrowser. Veröffentlichung anzeigen öffnet die GitHub-Seite der Veröffentlichung. havRemote installiert keine Updates und ersetzt keine Programmdateien.

Datenschutz: Update-Suchen verwenden die öffentliche GitHub-Releases-API des Projekts über HTTPS. Es werden weder ein GitHub-Konto noch ein Zugriffstoken oder Repository-Geheimnis benötigt. GitHub erhält die gewöhnlichen Verbindungsdaten einer HTTPS-Anfrage, beispielsweise die öffentliche IP-Adresse.

Sicherheit

  • SFTP oder FTPS bevorzugen. Unverschlüsseltes FTP überträgt Anmeldedaten und Dateiinhalte ungeschützt und erzeugt daher immer eine Warnung.
  • Vertrauensabfragen prüfen. Vergleichen Sie SFTP-Hostschlüssel-Fingerabdrücke oder FTPS-Zertifikatsinformationen mit einem Wert aus einem unabhängigen, vertrauenswürdigen Kanal.
  • FTPS-Prüfung kontrolliert, ob das Serverzertifikat vertrauenswürdig ist und zum Hostnamen passt. Eine gespeicherte Ausnahme merkt sich den öffentlichen Schlüssel des Zertifikats nur für diesen Host und Port. Sie ist nur für ein zeitlich gültiges, selbstsigniertes Zertifikat erlaubt, dessen einziges Problem ein fehlender vertrauenswürdiger Aussteller ist. Ablauf, erkannter Widerruf, abweichende Hostnamen oder andere Fehler bei der Zertifikatsprüfung werden dadurch nicht umgangen.
  • SFTP-Vertrauen ist an Host und Port gebunden. Unbekannte Schlüssel können einmalig oder dauerhaft akzeptiert werden. Ein geänderter Schlüssel bleibt gesperrt bis Sie ihn ausdrücklich ersetzen.
  • Geheimnisse wie Passwörter und Passphrasen privater Schlüssel werden niemals in der Einstellungsdatei oder im Schnellverbindungsverlauf gespeichert. Gespeicherte Zugangsdaten werden im Anmeldedatenspeicher des Betriebssystems aufbewahrt.
  • Interaktive Antworten wie TOTP-Codes werden nur für den aktuellen Anmeldevorgang verwendet und niemals gespeichert.
  • Diagnosemeldungen werden vor der Anzeige bereinigt. Prüfen Sie trotzdem Pfade und Servermeldungen, bevor Sie Bildschirmfotos oder Protokollauszüge weitergeben.
  • Pfadsicherheit weist Pfade zurück, die außerhalb des gewählten Ziels liegen, sowie unsichere Dateinamen oder Namenskonflikte.

Version 0.1.0 - 2026-09-17

Problemlösung

Ich kann keine Verbindung herstellen
  • Prüfen Sie Protokoll, Host und Port. Das Host-Feld darf kein ftp://, sftp://, keinen Pfad und keinen Port enthalten.
  • Prüfen Sie, ob der Server die gewählte Anmeldeart akzeptiert und seine Firewall die Verbindung zulässt.
  • Ein FTP/FTPS-Server kann eine inaktive Sitzung trennen, während die letzte Verzeichnisauflistung sichtbar bleibt. havRemote kann die Verbindung beim nächsten Vorgang automatisch erneut herstellen. Eine erfolgreiche Wiederverbindung erzeugt im Meldungsprotokoll den Eintrag Reconnected to the FTP server (erneut mit dem FTP-Server verbunden). Schlägt der Vorgang fehl, meldet havRemote den Fehler. havRemote sendet keine regelmäßigen Befehle, nur um eine inaktive Sitzung offen zu halten.
  • Eine FTP-Antwort 530 bedeutet, dass die Anmeldung abgelehnt wurde oder die Sitzung nicht mehr angemeldet ist. Das kann auch geschehen, wenn eine Dateioperation eine neue Verbindung benötigt. Prüfen Sie Ihre Anmeldedaten und die Zugriffsregeln des Servers und verbinden Sie sich vor einem erneuten Versuch neu.
  • Stellen Sie bei passivem FTP/FTPS sicher, dass die passiven Datenports des Servers durch dessen Firewall und das Netzwerk erreichbar sind. Diese Verbindungen werden über EPSV oder PASV ausgehandelt.
  • Erlauben Sie bei aktivem FTP/FTPS eingehende Datenverbindungen in Ihrer Firewall und prüfen Sie, ob der Server Ihren Computer über die ausgewählte lokale Adresse erreichen kann. Lassen Sie Lokale Adresse im aktiven Modus (optional) leer, sofern Sie keine andere, diesem Computer bereits zugewiesene Adresse benötigen. Kann der Server keine lokale Adresse direkt erreichen, verwenden Sie den passiven Modus.
  • Testen Sie aktives FTP/FTPS, indem Sie ein Verzeichnis auflisten, eine Datei herunterladen und eine Datei hochladen. Diese Vorgänge verwenden die Datenverbindung, das Umbenennen dagegen nicht. Eine FTP-Antwort 550 beim Umbenennen weist auf ein Problem mit der Dateioperation hin, etwa dem Pfad oder den Zugriffsrechten, nicht auf einen Fehler der Datenverbindung im aktiven Modus.
  • Lesen Sie die vollständige Fehlermeldung im Protokoll, einschließlich Erklärung, FTP-Antwort und Clientfehlercode (als CURLcode angezeigt). Serverantworten und Clientfehlercodes sind unterschiedliche Angaben: FTP-Antwort 550 ist nicht dasselbe wie CURLcode 55. Die zuletzt empfangene FTP-Antwort allein erklärt den Fehler möglicherweise nicht. Geben Sie beim Melden eines Problems die vollständige Nachricht an, prüfen Sie aber Namen, Pfade und Servermeldungen vor dem Weitergeben.
  • Eine DEBUG-Meldung bedeutet nicht zwangsläufig, dass eine Aktion fehlgeschlagen ist. Sie kann einen vom Server nicht unterstützten Befehl beschreiben, für den havRemote anschließend erfolgreich eine Alternative verwendet hat. Fehlgeschlagene Aktionen werden separat mit einer Erklärung des Problems gemeldet.
  • Bei Problemen im aktiven Modus zeigen Debug-Meldungen außerdem die lokale Adresse und den Empfangsport, soweit verfügbar, sowie Einzelheiten zu Fehlern beim Verbindungsaufbau. Damit können Sie oder der Serveradministrator die Erreichbarkeit und Firewall-Regeln prüfen.
Eine entfernte SFTP-Operation schlägt fehl

Sofern verfügbar, enthält die Diagnose den Statusnamen und die Statusnummer des Servers, etwa Permission denied (SFTP status 3) für verweigerten Zugriff oder No such file (SFTP status 2) für eine nicht vorhandene Datei. Diese Angaben beschreiben einen Fehler bei einer Dateioperation, kein abgelehntes Passwort. Ein allgemeines Failure (SFTP status 4) nennt keine genaue Ursache. Prüfen Sie Pfad, Berechtigungen, freien Speicherplatz und die Serverprotokolle oder fragen Sie den Administrator. Anmelde- und Verbindungsfehler werden separat gemeldet.

Ein Zertifikat oder SFTP-Hostschlüssel hat sich geändert

Akzeptieren Sie die neue Identität erst, nachdem der Serveradministrator sie über einen unabhängigen, vertrauenswürdigen Kanal bestätigt hat. Eine geänderte Identität kann durch berechtigte Serverwartung entstehen, aber auch auf einen Abfangversuch oder unerwarteten Endpunkt hindeuten.

Besitzer/Gruppe oder Berechtigungen sind in der Serverliste leer

Der Server oder das verwendete Listenformat hat diese Metadaten nicht geliefert. Aktualisieren Sie das Verzeichnis nach vollständigem Verbindungsaufbau. Bleiben die Werte leer, weist das nicht zwangsläufig auf einen Fehler hin.

Pause, Abbrechen oder Erneut versuchen ist deaktiviert

Markieren Sie eine Übertragung in der passenden Ansicht Warteschlange, Fehlgeschlagen oder Abgeschlossen. Eine Aktion ist nur in Zuständen verfügbar, in denen sie sicher ausgeführt werden kann. Wählen Sie für wiederhergestellte Arbeit den zugehörigen Verbindungstab und verbinden Sie sich erneut mit dem ursprünglichen Server und exakt gleichen Endpunkt, bevor Sie Erneut versuchen verwenden.

Fortsetzen wird nicht angeboten

Die Metadaten von Quelle, Ziel oder Teildatei stimmen nicht mehr mit der aufgezeichneten Übertragung überein. Die erforderlichen Prüfungen beschreibt Teildateien und sicheres Fortsetzen. Verwenden Sie Überschreiben, Umbenennen oder Überspringen, statt an eine ungeprüfte Datei anzuhängen.

Eine extern bearbeitete Datei wurde nicht hochgeladen

Lassen Sie havRemote, den zugehörigen Verbindungstab und die Serververbindung während der Bearbeitung geöffnet. Prüfen Sie Warteschlange und Meldungsprotokoll. Steht der Upload unter Fehlgeschlagen, beheben Sie das Problem und verbinden Sie sich bei Bedarf erneut mit dem ursprünglichen Server und Endpunkt. Markieren Sie anschließend den Eintrag und wählen Sie Erneut versuchen. Ist kein wiederholbarer Eintrag mehr vorhanden, verwenden Sie die gemeldete Wiederherstellungskopie und laden Sie sie manuell hoch. Den Speicherort finden Sie unter Konfigurationsdateien und Speicherorte.

Das Design wurde nicht sofort geändert

Designänderungen erfordern einen Neustart der Anwendung. Änderungen an Sprache und externem Editor werden sofort angewendet.

Die Suche nach Updates schlägt fehl

Prüfen Sie, ob der HTTPS-Zugriff auf GitHub verfügbar ist und nicht von einer Firewall oder einem Proxy blockiert wird, und starten Sie anschließend erneut eine manuelle Suche. Fehler bei einer automatischen Suche werden ohne Dialog in das Meldungsprotokoll geschrieben. havRemote benötigt weder eine GitHub-Anmeldung noch ein Zugriffstoken.

Beim Start wird eine ungültige Konfiguration gemeldet

Notieren Sie Dateiname, Zeile und Spalte aus der Fehlermeldung. Schließen Sie havRemote, erstellen Sie eine Sicherung, korrigieren oder entfernen Sie die fehlerhafte Datei und starten Sie neu.
